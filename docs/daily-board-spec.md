# Личный канбан для macOS — спецификация первой версии

Статус: согласованный черновик. Дата: 8 октября 2026 года.

## Назначение и границы

Нативное приложение на Swift/SwiftUI для личного учёта текущих задач. Пользователь сам создаёт доски и колонки. Приложение не привязывает колонки к датам и не переносит задачи автоматически. Первая сборка ориентирована на macOS 26 и хранит данные локально на Mac.

В первую версию не входят синхронизация, экспорт, поиск в архиве и календарная логика. При первом запуске нет ни досок, ни колонок.

## Основной экран

- Слева — список досок; справа — колонки выбранной доски. Колонки прокручиваются горизонтально.
- Доски можно создавать, переименовывать и удалять. При удалении доски приложение предупреждает, что удалятся её колонки, активные и архивные задачи.
- Колонки можно создавать, переименовывать и переставлять. У колонки есть цветная полоса в заголовке. Цвет выбирается из небольшой палитры приятных пастельных цветов.
- При удалении непустой колонки пользователь выбирает: окончательно удалить находящиеся в ней активные задачи или перенести их в другую колонку этой доски. Если другой колонки нет, перенос недоступен; удаление можно отменить. Архивные задачи доски остаются в архиве, так как больше не привязаны к колонке.
- У каждой доски свой архив, доступный из основного экрана.

## Задачи

- Quick Task: ввод названия и Enter создают задачу в выбранной колонке. Новая задача появляется в начале незавершённых. Пустое название или название из пробелов не создаёт задачу.
- Обычный клик по карточке открывает попап редактирования поверх доски. В нём можно изменить название, дополнительное описание и цвет карточки. Цвет отображается полосой сбоку. Кнопки «Сохранить» и «Отмена»; до сохранения изменения остаются черновиком. Название после удаления крайних пробелов не может быть пустым. Если есть несохранённые изменения, клик вне попапа или Esc вызывают вопрос: сохранить, не сохранять или вернуться к редактированию. Без изменений попап закрывается сразу.
- Галочка меняет статус задачи. Незавершённые находятся сверху, завершённые — снизу. Между ними отображается лёгкий разделитель «Завершено», когда в колонке есть завершённые задачи.
- При завершении задача переходит в начало группы завершённых; при снятии галочки — в начало группы незавершённых.
- Задачи можно вручную переставлять внутри своей группы и переносить между колонками. Перенос сохраняет статус и ставит задачу в начало соответствующей группы колонки назначения.
- У задачи есть действия «Перенести…», «Архивировать» и «Удалить». Удаление окончательное.

## Выделение и групповые действия

- ⌘-клик выделяет отдельные карточки из любых колонок текущей доски, Shift-клик — диапазон внутри одной колонки. При смене доски выделение сбрасывается. Выбранные задачи можно переносить вместе перетаскиванием или через меню действий.
- Меню колонки содержит быстрые команды «Перенести завершённые…», «Архивировать завершённые» и «Выбрать все завершённые». Они избавляют от ручного выделения завершённых задач. «Выбрать все завершённые» заменяет текущее выделение завершёнными задачами этой колонки.
- «Перенести завершённые…» запрашивает колонку назначения и меняет только колонку; статус задач сохраняется.
- «Архивировать завершённые» убирает завершённые задачи этой колонки с доски в архив этой же доски. Архивирование заполняет `archivedAt` и очищает `columnId`, сохраняя связь задачи с доской.

## Архив

- Архив каждой доски — простой список без поиска. Порядок карточек в архиве не принципиален.
- Для архивной задачи доступны «Восстановить…» и «Удалить».
- При восстановлении приложение всегда спрашивает колонку этой доски. Выбранная колонка записывается в `columnId`, `archivedAt` очищается, а задача появляется в начале группы, соответствующей её сохранённому статусу.
- Если на доске нет колонок, восстановление недоступно до создания колонки; задача остаётся в архиве.
- Удаление архивной задачи окончательное.

## Концептуальная структура данных

SwiftData может хранить эти сущности локально. Таблицы ниже описывают логическую схему, а не формат внутренних файлов SwiftData.

### Board

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | UUID, PK | Устойчивый идентификатор доски |
| `title` | String | Название |
| `position` | Int | Порядок в боковой панели |
| `createdAt` | Date | Дата создания |
| `updatedAt` | Date | Дата последнего изменения |

### Column

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | UUID, PK | Устойчивый идентификатор колонки |
| `boardId` | UUID, FK → Board | Доска-владелец |
| `title` | String | Название |
| `colorId` | String | Идентификатор цвета из палитры |
| `position` | Int | Порядок на доске |
| `updatedAt` | Date | Дата последнего изменения |

### Task

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | UUID, PK | Устойчивый идентификатор задачи |
| `boardId` | UUID, FK → Board | Доска-владелец, сохраняется после архивирования |
| `columnId` | UUID?, FK → Column | Колонка задачи; `null` после архивирования и для будущих задач без колонки |
| `title` | String | Название |
| `description` | String | Дополнительное описание |
| `colorId` | String? | Цвет из палитры; `null` означает обычную карточку |
| `isCompleted` | Bool | Состояние галочки |
| `position` | Int | Порядок внутри группы своего статуса |
| `archivedAt` | Date? | `null` у активной задачи; дата переноса в архив у архивной |
| `createdAt` | Date | Дата создания |
| `updatedAt` | Date | Дата последнего изменения |

Связи: `Board 1 → N Column`, `Board 1 → N Task`, `Column 1 → N` активных `Task`. Колонка задачи, если указана, всегда принадлежит той же доске, что и задача. Архив определяется заполненным `archivedAt`, а не пустым `columnId`.

В первой версии действует инвариант: каждая активная задача (`archivedAt = null`) имеет `columnId` существующей колонки своей доски. Ни одна операция первой версии не создаёт активную задачу без колонки. Поле остаётся необязательным в схеме для архива и возможного будущего режима списка. Архивная задача имеет `archivedAt != null` и `columnId = null`.

При архивировании меняются `archivedAt`, `columnId` и служебное `updatedAt`; остальные поля задачи сохраняются. `updatedAt` обновляется и при восстановлении, поскольку фиксирует время последнего изменения записи.

Для отображения колонки задачи сортируются сначала по `isCompleted` (незавершённые выше), затем по `position`. Статус выделения и открытый попап относятся к состоянию интерфейса и в базе не хранятся. Цвета хранятся как идентификаторы палитры, чтобы их можно было изменить в будущих версиях приложения без изменения всех записей.

При групповом переносе в другую колонку задачи попадают в начало соответствующих групп статуса. Внутри каждой группы сохраняется их исходный визуальный порядок; если источников несколько, сначала идут задачи из более левой колонки. Положение курсора между карточками колонки назначения не меняет это правило.

## Надёжность сохранения

Операции, затрагивающие несколько записей (групповой перенос или архивирование, удаление колонки с удалением или переносом задач, удаление доски), выполняются атомарно: сохраняются все изменения либо не сохраняется ни одно. Интерфейс показывает успешный результат только после успешного сохранения. При ошибке состояние доски остаётся прежним, а пользователь видит сообщение об ошибке; несохранённый текст открытого попапа остаётся доступным для повторной попытки.

## Порядок разработки

1. Локальное хранилище, модели и создание досок.
2. Колонки, боковая панель и Quick Task.
3. Карточка, попап с черновиком, галочка и разделение по статусу.
4. Ручная сортировка, перенос и множественное выделение.
5. Быстрые групповые действия, архив, восстановление и удаление.
6. Проверка основных сценариев и визуальная полировка.

## Основные сценарии приёмки

1. Пользователь создаёт доску и две колонки, добавляет задачи в одну из них; новые задачи появляются сверху.
2. Отмеченная задача перемещается под разделитель, а снятие галочки возвращает её наверх незавершённых.
3. «Перенести завершённые…» переносит только завершённые задачи выбранной колонки и сохраняет их галочки.
4. Несколько выбранных задач можно перенести перетаскиванием в другую колонку; их статусы сохраняются.
5. Архивирование убирает задачу с доски; восстановление запрашивает колонку и возвращает задачу с прежним статусом.
6. После перезапуска приложения доски, колонки, задачи, их порядок, цвета и архив остаются на месте.
