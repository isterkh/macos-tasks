# Контекст проекта для ИИ-агентов

## Что это

Tasks (в коде — DailyBoard) — нативный личный канбан для macOS 26. Пользователь вручную создаёт доски и колонки, ведёт задачи, меняет их порядок, переносит между колонками и архивирует. Данные хранятся только на этом Mac. Синхронизация, учёт дат, автоматический перенос задач, экспорт и поиск по архиву в первую версию не входят.

Продуктовые правила, модель данных и сценарии приёмки описаны в [docs/daily-board-spec.md](docs/daily-board-spec.md). Инструкции по сборке и использованию находятся в [README.md](README.md). При расхождении документа с кодом проверьте фактическое поведение и явно укажите расхождение в результате работы; не меняйте требования молча.

## Технологии и структура

- Swift 6, SwiftUI, SwiftData, macOS 26. Проект Xcode: `DailyBoard.xcodeproj`; его исходная конфигурация — `project.yml` (XcodeGen).
- `Sources/DailyBoardApp.swift` — точка входа приложения.
- `Sources/Models.swift` — сохраняемые `BoardEntity`, `ColumnEntity`, `TaskEntity` и снимки `BoardRecord`, `ColumnRecord`, `TaskRecord` для интерфейса.
- `Sources/BoardStore.swift` — `@MainActor`-хранилище, все операции с SwiftData, сортировка и публикация состояния для UI.
- `Sources/RootView.swift` — выбор и управление досками; `Sources/BoardView.swift` — колонки, карточки, выделение, редактор и перетаскивание; `Sources/ArchiveView.swift` — архив доски; `Sources/Palette.swift` — цвета.
- `Tests/BoardStoreTests.swift` — проверки хранилища; `UITests/DailyBoardUITests.swift` — основные пользовательские сценарии.

## Модель и инварианты

- Доска владеет колонками и задачами. Активная задача имеет `archivedAt == nil` и `columnID` существующей колонки той же доски.
- Архивная задача имеет `archivedAt != nil` и `columnID == nil`, но сохраняет `boardID`, статус и содержимое. Восстановление всегда требует колонку той же доски.
- Порядок колонок задаёт `position`. В колонке незавершённые задачи идут выше завершённых; `position` задаёт порядок внутри каждой группы. Новая задача и задача с изменённым статусом попадают в начало своей группы.
- Названия досок, колонок и задач после удаления крайних пробелов не могут быть пустыми. Цвета сохраняются как ID палитры.
- Групповые изменения должны сохраняться атомарно. `BoardStore.transact` выполняет транзакцию, перечитывает снимки после успеха и откатывает контекст с сообщением об ошибке при сбое. Не обходите этот путь прямыми изменениями модели из UI.
- Данные пользователя находятся в `~/Library/Application Support/com.isterkh.DailyBoard/Tasks.store`. Не очищайте это хранилище при разработке или проверке. Тесты используют хранилище в памяти либо отдельный временный файл; UI-тесты запускают приложение с `--ui-testing`.

## Как вносить изменения

1. Перед изменением поведения сверяйте задачу с `docs/daily-board-spec.md` и соответствующим кодом. Если меняется продуктовое правило, обновляйте спецификацию вместе с реализацией.
2. Операции над данными размещайте в `BoardStore`; состояние выбора, фокуса, диалогов и несохранённого черновика держите в SwiftUI. Не сохраняйте временное состояние интерфейса в SwiftData.
3. Сохраняйте ограничения по принадлежности доске при переносе и восстановлении задач. При удалении колонки учитывайте отдельно активные и архивные задачи. При удалении доски учитывайте обе группы.
4. Изменение схемы SwiftData рассматривайте как изменение формата пользовательских данных: продумайте совместимость существующего хранилища и проверку открытия старых данных.
5. Для изменений логики хранения проверяйте значимый сценарий в `BoardStoreTests`; для изменений взаимодействия при необходимости проверяйте сценарий в `DailyBoardUITests`. Не добавляйте тест, который только повторяет реализацию.

## Сборка и проверка

Откройте `DailyBoard.xcodeproj` в Xcode 26.4 или новее. Из терминала:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild \
  -project DailyBoard.xcodeproj -scheme DailyBoard \
  -derivedDataPath DerivedData build
```

Для тестов замените `build` на `test`. UI-тестам может потребоваться системное разрешение macOS на управление приложением. Если меняется `project.yml`, пересоздайте проект через `xcodegen generate` и проверьте, что Xcode-проект соответствует конфигурации.
